# Gome Remote Mac 에이전트

상태: rev 4 (구현 중 화질 조정, 2026-10-15; 캡처 후 축소 2026-10-16). 설계 결정 리뷰 1·2라운드(`ad97e5a`, `a3e7797`) 지적 반영. 등급 F.
날짜: 2026-10-14. 기준: `main` `172b2b5`. 작업 브랜치: `feat/mac-agent`.
근거 시험: 시험판 브랜치 `worktree-mac-agent-spike`(비공개, main에 넣지 않음).

공개 저장소이므로 오너의 tailnet 로그인, 기기 이름, tailnet IP를 쓰지 않는다. 아래
`100.64.0.10`(게이트웨이 서버), `100.64.0.20`(Mac 호스트)은 자리표시자다.

## 1. 목적과 성공 기준

오너가 말한 목적: Mac 원격 조작이 Mac→Mac 화면 공유처럼 빠르게. 자체 압축으로 보내는
방식을 Gome Remote 안에 직접 만든다(2026-10-08). Mac에 별도 프로그램을 설치하는 것은
괜찮다. 시험판 결과를 보고 본 개발 진행을 결정했다(2026-10-14).

성공 기준. 임계값은 측정 전에 고정한 값이며 측정 결과에 맞춰 옮기지 않는다. 측정법은 8절.

- S1. 앱에서 Mac 타일을 누르면 새 방식으로 Mac 화면이 보이고 마우스(이동, 세 버튼, 드래그,
  스크롤)·키보드(한글, 한/영 포함)·텍스트 입력 창·해상도 자동·전체 화면·다시 연결이 Ubuntu
  대상과 같은 흐름으로 동작한다.
- S2. 클릭→화면 반영, **측정 클라이언트마다**(게이트웨이 서버의 headless Chrome, 오너 Windows
  앱, 오너 Mac 앱), 30회 × 3번:
  - 중앙값 100 ms 이하이고, 같은 시간대 같은 클라이언트의 VNC 경로 중앙값의 0.6배 이하.
  - p95 150 ms 이하(VNC의 측정 p95 193 ms와 구별되는 값).
  - 1초를 넘는 표본 0개.
- S3. 지속 동작에서 멈춤 없음: 60초 드래그·스크롤 동안 수신 측 통계의 멈춤(freeze) 중 500 ms를
  넘는 것이 0개(클라이언트마다 1번).
- S4. 대역폭이 모자란 경로: 게이트웨이 서버 측정 클라이언트의 수신을 5 Mbps로 제한했을 때 1초를
  넘는 멈춤 0개, 중앙값 200 ms 이하. 3 Mbps 미만 경로는 지원 하한 밖이다(화질과 지연 저하를
  허용하되 연결은 유지).
- S5. 오너가 평소 쓰는 Windows·Mac 기기에서 체감이 VNC보다 확실히 낫다(오너 판정. 원하면
  Mac→Mac 화면 공유와 나란히 비교한다).
- S6. 인가 범위를 넓히지 않는다: Mac을 조작할 수 있는 주체는 지금처럼 게이트웨이 인가
  (Tailscale 로그인)를 통과한 기기뿐이다.

## 2. 사실 확인 (2026-10-08 ~ 10-14)

- Mac 호스트: Apple M4, macOS 27.0.1, 4K 디스플레이(논리 1920×1080 @2x). Rust 툴체인과
  Xcode Command Line Tools 있음. 오너가 콘솔에 로그인해 쓰는 기기다. 오너 계정은 admin이며
  `sudo`에 비밀번호가 필요하다.
- 현재 VNC 경로(게이트웨이 0.2.0 `a9c909f`, guacd, Mac 계정 인증, 16비트 색, local cursor)는
  동작한다. 2026-10-08과 10-14에 이 경로로 Mac을 실제 조작해 측정했다(게이트웨이 서버의
  headless Chrome, 캔버스 픽셀 폴링): 중앙값 171~182 ms, p95 193 ms, 가끔 1~2초 멈춤. 결과
  파일과 조건은 비공개 인계 기록에 있다. 이 측정은 redesign V4(Mac 계정 인증으로 조작)의 증거도
  된다(`docs/verification.md` 갱신은 구현에서 한다). macOS는 Apple이 아닌 클라이언트에 옛 RFB
  경로만 준다.
- 시험판(ScreenCaptureKit → VideoToolbox H.264 → WebRTC(str0m) 직접 전송, 입력은 data
  channel → `CGEventPost`). 측정 클라이언트는 게이트웨이 서버의 headless Chrome(소프트웨어
  디코드, 직접 경로 RTT 5 ms)뿐이고, 페이지는 에이전트의 http 출처에서 열렸다. VNC와 측정
  방식이 다르다(에이전트는 `requestVideoFrameCallback`, VNC는 캔버스 폴링). 이 편향은 새 방식에
  불리한 쪽이다.
  - 2560×1440@60: 중앙값 77 ms, p95 99~110 ms, 유실 0. 4K@45: 중앙값 104 ms, p95 123 ms.
  - 단계 중앙값(1440p): Mac의 Chrome이 클릭을 받아 다시 그림 38 ms(어느 원격 방식에도 공통),
    인코딩 10 ms, 네트워크 6 ms, 수신 측 지터 버퍼·디코드·vsync 25 ms, 입력 전달 3 ms.
  - M4 하드웨어 인코더는 4K에서 약 48 fps가 상한. 에이전트 CPU 1~2%. 고정 비트레이트이고 혼잡
    제어가 없었다.
  - 초기 0.5~2.9초 멈춤의 원인: 클라이언트가 `video/rtx`를 코덱 선호에서 빼 재전송이 없었다.
    RTX와 UDP 소켓 버퍼 4 MiB로 해결. 페이싱은 효과 없음.
  - 미해결: 정지 화면에서 재전송 간격을 1초로 두면 변화 프레임의 10~15%가 수신 측에서
    250~700 ms 머문다(원인 미상, 소프트웨어 디코더에서만 관찰). 100 ms 간격 재전송이 이를
    가린다(정지 시 0.35~0.9 Mbps). 하드웨어 디코더에서의 동작은 모른다(P2).
- 권한(TCC): 화면 기록과 손쉬운 사용 허용은 실행 파일의 **경로 + 코드 서명 요구 조건**에
  묶인다. 전용 키체인의 자체 서명 인증서로 다시 서명한 재빌드는 허용을 유지했다(여러 번).
  `AXIsProcessTrusted`는 허용 후 프로세스를 다시 시작해야 true가 된다. 허용 클릭은 Mac
  화면에서 해야 한다. SSH 세션에서는 로그인 키체인이 잠겨 있다.
- **화면 기록 30일 재확인**: macOS 27은 화면 기록을 쓰는 앱마다 재확인 일정을 둔다. Mac의
  `ScreenCaptureApprovals.plist`에 시험판 항목이 `kScreenCapturePrivacyHintPolicy` 2592000초
  (30일), 다음 날짜 2026-11-12로 기록돼 있다. 재확인 창이 뜰 때 캡처가 멈추는지는 모른다(P4).
  Apple의 지속 캡처 entitlement는 유료 개발자 프로그램과 Apple 승인이 필요해 범위 밖이다.
- LaunchAgent는 `ProcessType=Interactive`가 없으면 프레임이 약 30 fps로 조절된다. 디스플레이가
  잠들면 캡처가 "no displays"로 실패한다.
- 게이트웨이 페이지는 Tailscale Serve의 https 출처에서 오고 CSP `connect-src 'self'`다.
  페이지가 Mac의 http 주소를 직접 부를 수 없다(혼합 콘텐츠·CSP). WebRTC 미디어(UDP)는 CSP
  대상이 아니다. Electron 앱은 모든 권한 요청을 거부하지만 수신 전용 WebRTC에는 권한이 필요
  없다. Chrome/Electron은 기본으로 자기 host 후보를 mDNS 이름으로 가린다.
- 게이트웨이의 자격 증명 파서는 `username`·`password` 외의 키와 `password` 없는 항목을 거부하고,
  거부하면 파일 전체가 무효다(시작 거부, 또는 실행 중이면 모든 대상 "설정 필요"). 자격 증명
  파일은 백업하지 않는다(redesign D2).

## 3. 선행 시험 (구현 착수 전, 시험판으로)

각 시험은 통과·실패 때 할 일을 미리 정한다.

- P1. 잠금 화면. 오너에게 알린 뒤 Mac을 잠그고 (a) ScreenCaptureKit이 잠금 화면을 캡처하는지,
  (b) `CGEventPost` 키 입력이 비밀번호 칸에 들어가는지(의미 없는 문자 몇 개로 점이 찍히는지만
  보고 지운다, 비밀번호는 쓰지 않는다), (c) VNC 타일로 잠금 화면에 비밀번호를 칠 수 있는지를
  본다.
  - (a)(b) 통과 → 에이전트로 잠금 해제까지 한다.
  - (a) 또는 (b) 실패, (c) 통과 → 에이전트는 상태 "잠김"을 보이고, 잠금 해제는 VNC 타일로 한다
    (D9에서 VNC 타일을 계속 둔다). 진행.
  - (c)까지 실패 → 지금도 잠금 해제 경로가 없다는 뜻이므로 후퇴가 아니다. 진행하고 오너에게
    알린다.
  - 결과(2026-10-16, 오너의 Mac): (a)(b) 통과 — 에이전트가 잠금 화면을 캡처했고 비밀번호 칸에
    입력이 들어갔다. 그래서 첫 번째 갈래로 간다: 에이전트로 잠금 해제까지 한다
    (`REFUSE_WHEN_LOCKED = false`, `LOCKED_TILE_ENABLED = true`). (c)는 VNC 타일로 잠금 화면은
    보였으나 친 글자가 나타나지 않았다(원인 미확인). VNC 타일은 D9대로 대체 경로로 남긴다.
- P2. 실제 클라이언트. 오너 Windows 기기와 Mac 기기의 Chrome으로 시험판에 접속해 (a) ICE 성립과
  선택된 후보 쌍(직접/DERP 중계), (b) 측정 도구로 2560×1440 클릭→반영 30회, (c) 정지 후 변화
  프레임 보류(1초 재전송 간격으로 30회), (d) 디코더 이름(`getStats`의 decoderImplementation)을
  기록한다.
  - ICE 실패 → mDNS 후보를 받기 위한 에이전트 후보 규칙을 고친다(D2의 후보 필터는 tailnet 주소의
    prflx 후보를 허용해야 한다). 고쳐도 실패하면 오너에게 보고하고 멈춘다.
  - (b)가 S2를 못 넘음 → 원인(경로, 디코더)을 찾아 고친다. S2 임계값은 바꾸지 않는다. DERP
    경로라면 직접 경로를 만드는 쪽을 먼저 본다. 해결이 안 되면 오너에게 보고하고 멈춘다.
  - (c)에서 하드웨어 디코더가 100 ms 재전송으로도 보류 → 정지 화면 재전송 방식을 다시 정하는
    것이 구현 첫 과제가 된다(S2·S3이 판정).
- P3. 갱신 시 허용 유지. 시험판을 root 소유 경로로 옮겨 오너가 허용한 뒤, **D6의 실제 절차**(전용
  키체인 인증서로 서명, hardened runtime, sudo로 교체)로 두 번 갱신해 허용이 유지되는지 본다.
  hardened runtime을 켠 상태에서 캡처·입력이 그대로 되는지, 인증서를 새로 만들면 허용이 풀리는지도
  본다.
  - 유지 → D6대로.
  - 풀림 → 갱신마다 재허용이 필요하다는 뜻이다. 재허용은 VNC 타일로 원격에서도 할 수 있으므로
    진행하되, 갱신 절차에 재허용 단계를 넣는다.
- P4. 30일 재확인. 시험판 항목의 재확인 날짜(2026-11-12)에 실제로 일어나는 일을 관찰한다:
  캡처가 계속되는지, 멈춘다면 ScreenCaptureKit이 오류를 돌려주는지 검은(내용 없는) 프레임을
  정상처럼 돌려주는지, 창이 어디에 뜨는지, VNC 타일로 그 창을 누를 수 있는지. 날짜를 앞당기는 조작은
  하지 않는다. 구현과 병행하며, 결과가 나오기 전 전환(9절 5단계)은 하지 않는다.
  - 캡처 계속 → D5 그대로.
  - 오류로 멈춤 → 에이전트 상태 "권한 필요"(D5). VNC 타일로 창을 눌러 복구.
  - 검은 프레임 → 에이전트가 일정 시간 내용 없는 프레임만 오면 상태를 "권한 필요(의심)"로 바꾼다
    (`lastCaptureAt`은 내용 있는 프레임 기준). 복구는 같다.
  - VNC 타일로도 창을 누를 수 없음 → 재확인 날짜마다 Mac 앞에서 눌러야 한다는 뜻이다. 오너에게 알리고,
    9절 6단계 점검에 재확인 날짜 안내를 넣는다(전환 여부는 오너가 정한다).

## 4. 결정

### D1. 연결 정보만 게이트웨이를 거치고, 영상·입력은 클라이언트와 Mac이 직접 주고받는다

- 페이지는 지금처럼 게이트웨이 출처에서 열린다. Mac 대상은 새 연결 방식 `agent`를 쓴다.
- 페이지가 `RTCPeerConnection`(ICE 서버 없음)으로 offer를 만들고 후보 수집을 마친 뒤(1.5초
  제한) 게이트웨이에 보낸다. 게이트웨이가 에이전트에 전달하고 answer를 돌려준다. 이후 미디어와
  data channel은 tailnet 위 UDP로 직접 오간다.
- 게이트웨이는 영상을 보지 않는다. 게이트웨이와 서버 부하·지연이 늘지 않는다.
- 버린 안: (a) 에이전트가 자기 페이지를 제공 — 앱·화면이 둘로 갈리고 https 페이지에서 http를
  부를 수 없다. (b) 영상도 게이트웨이 경유 — 한 단계 늘어 느려지고 서버 CPU를 쓴다. 직접 경로가
  끝내 안 되는 기기용 중계(TURN)는 P2 결과가 요구할 때만 다시 본다.

### D2. 인가와 신뢰 경계

- 사용자 인가는 바뀌지 않는다: `/api/*`의 Tailscale 로그인 허용 목록과 Origin 검사(redesign
  D3)를 새 경로도 그대로 쓴다.
- 게이트웨이↔에이전트: 대상별 무작위 토큰(32바이트, base64url). 에이전트는
  `Authorization: Bearer`를 상수 시간 비교한다. 게이트웨이는 자격 증명 파일의 그 대상 항목에
  `agentToken`으로 보관한다. 입력 방법은 redesign D2와 같다(`set-credential.mjs <대상 ID> --agent-token`,
  에코 없음, argv 미사용, 원자적 쓰기). 항목 모양은 대상 방식이 정한다:
  `agent` 대상은 `{agentToken}`, `rdp`·`vnc` 대상은 지금과 같다. 한 항목에 둘을 섞지 않는다.
- 에이전트 HTTP는 Mac의 tailnet 주소에만 바인딩하고, 설정된 게이트웨이 tailnet 주소에서 온
  연결만 받는다. `Host`는 바인딩 주소:포트와 같아야 하고 `Origin`이 있으면 거부한다. 인증
  실패가 이어지면 응답을 늦춘다(정상 게이트웨이 요청은 늦추지 않는다).
- 이 HTTP는 평문이지만 tailnet(WireGuard)으로 암호화된다.
- 미디어 보안: DTLS-SRTP 지문이 offer/answer에 실려 게이트웨이(https)와 tailnet을 거쳐
  교환된다. 에이전트는 원격 후보 중 tailnet 주소(IPv4 tailnet 대역, IPv6 `fd7a:115c:a1e0::/48`)가
  아닌 것을 버린다. 브라우저가 host 후보를 mDNS로 가리면 연결 점검으로 드러나는 tailnet 주소의
  prflx 후보만 받는다.
- 신뢰 경계: 게이트웨이 인가 = Mac 조작(redesign D2와 같다). 게이트웨이 서버를 장악하면 토큰으로
  Mac 화면·입력을 조작할 수 있다. 이 서버에는 VNC 대체 경로용 Mac 계정 비밀번호도 계속 남는다
  (D9). 이 둘을 합친 경계는 지금(비밀번호만)보다 넓지 않다.
- Mac 안의 위협: 같은 사용자 권한으로 도는 다른 코드가 에이전트의 권한(화면 기록·손쉬운 사용)을
  빌려 쓰지 못하게 한다.
  - 실행 파일은 root 소유 경로에 둔다(D6). 바꿔치기하려면 관리자 비밀번호가 필요하다.
  - 설정(`agent.json`: 바인딩 주소, 포트, 게이트웨이 주소)도 root 소유(644)로 두고, 에이전트는
    설정 경로를 인자나 환경 변수로 받지 않는다.
  - 서명에 hardened runtime을 켜 라이브러리 주입(DYLD 환경 변수)과 디버거 부착을 막는다.
  - 토큰 파일은 에이전트가 읽어야 하므로 사용자 소유 600이다. 같은 사용자 코드가 토큰을 읽어도
    에이전트는 게이트웨이 주소에서 온 연결만 받으므로 그것만으로는 조작할 수 없다.
  - 남는 위험: 같은 사용자 코드가 LaunchAgent를 내려 에이전트를 멈출 수 있다(서비스 거부). 받아
    들인다.

### D3. 영상

- 캡처: ScreenCaptureKit, 주 디스플레이 하나, `showsCursor=false`(D4 포인터), queue depth 3,
  NV12. 디스플레이가 잠들어 있으면 세션 시작 때 사용자 활동 assertion으로 깨우고, 세션 동안
  디스플레이 잠자기를 막는다.
- 크기: 페이지가 요청한 크기(자동 = 뷰어 CSS 크기 × devicePixelRatio, 짝수 내림, 640×480 ~
  3840×2160로 자름 — 현재 `resolution.ts` 규칙)에 Mac 화면 비율을 유지해 맞춘다. 세션 중 바뀌면
  스트림 설정만 갱신한다. 2560×1440 이하 화소 수는 60 fps, 그보다 크면 45 fps.
  스트림이 화면보다 작으면 ScreenCaptureKit에는 화면의 실제 화소 크기로 캡처를 요청하고 VideoToolbox
  화소 전송으로 스트림 크기까지 줄인다(ScreenCaptureKit 자체 축소는 글자가 흐리다. 3840×2160 화면에서
  측정: 2132×1200 출력의 윤곽 대비가 좋은 리샘플러의 절반 미만, 정확히 절반인 1920×1080에서도 같음.
  `captureResolution`은 너비·높이를 지정하면 출력이 바뀌지 않았다).
- 인코딩: VideoToolbox H.264 constrained baseline, 하드웨어, real-time, 저지연 rate control,
  B 프레임 없음, PLI/FIR와 새 시청자에 키프레임, 주기 키프레임 3초. 양자화 상한
  (`MaxAllowedFrameQP`) 30: 보통 콘텐츠에서는 인코더가 이미 30 아래여서 측정된 효과는 없고,
  저지연 rate control이 더 거칠게 양자화하는 콘텐츠에 대한 보호용으로 둔다.
- 비트레이트: 화소 수별 목표(1440p 이하 20 Mbps, 4K 35 Mbps, 사이는 화소 수에 비례)를 상한으로
  삼고 세션을 그 값에서 시작해, str0m의 대역폭 추정(TWCC)에 맞춰 내린다. 하한 2 Mbps. S4가
  판정한다. 추정이 하한 아래로 떨어지면(정지 화면은 보내는 양이 적어 추정기가 확인된 전송률의
  0.85배로 곤두박질친다) 추정기를 하한에서 다시 시작한다: str0m은 추정의 1.1배로 송신을 조절하므로
  추정이 수십 kbps가 되면 키프레임과 클릭 프레임이 수 초씩 밀린다. 화면이 300 ms 동안 정지하면 마지막 프레임을 키프레임으로 한 번 더 인코딩하되 그
  프레임만 비트레이트를 현재 목표의 2배(상한의 1.5배까지)로 올려 선명하게 만들고, 곧 원래
  값으로 되돌린다. 정지 구간마다 한 번이며 새 프레임이 오면 구간이 끝난다.
- 전송: str0m, H.264 + RTX, playout-delay(0,0), abs-capture-time, UDP 소켓 버퍼 4 MiB.
  정지 화면은 100 ms 간격으로 마지막 프레임을 다시 보낸다(2절 미해결 항목의 우회. P2 결과에 따라
  바꾼다).
- 페이지: 수신 전용 video 트랜시버, 코덱 선호 H.264 + `video/rtx`(빠지면 멈춤이 재발하므로
  테스트로 고정), `jitterBufferTarget`·`playoutDelayHint` 0, `object-fit: contain`.
- 코덱: H.264. AV1은 Apple 실리콘에 하드웨어 인코더가 없어 뺐다(오너에게 2026-10-08 설명, O0).

### D4. 입력

- data channel `input` 하나(순서 보장·신뢰 전송). JSON 메시지, 메시지당 512바이트 이하
  (`text`만 8 KiB 이하, `clipboard`만 256 KiB 이하), 범위를 벗어난 값은 버린다.
  - `pointer {x,y}` 0..1 정규화(표시된 영상 내용 영역 기준), `button {b:0|1|2, down, x, y}`,
    `wheel {dx, dy}`(픽셀, 자름), `key {code, down}`(`KeyboardEvent.code`), `text {s}`,
    `release {}`(눌린 키·버튼 모두 놓기), `size {w,h}`.
  - 클립보드(2026-10-19, 에이전트 0.2.0): `clipboard {text, concealed?}`(`text`는 비어 있지 않고
    UTF-8 64 KiB 이하; 이 메시지만 `text`처럼 512바이트 한도의 예외이며 메시지 전체는 256 KiB 이하)와
    `clipboard-watch {on}`. 잠금이 아니면 `clipboard`를 NSPasteboard에 쓰고(`currentHostOnly`,
    `concealed`이면 `org.nspasteboard.ConcealedType` 표시), 잠겨 있으면 메모리에만 들고 있는다.
    `clipboard-watch`가 켜져 있는 동안만 약 300 ms마다 `changeCount`를 보고, 켤 때의 값을 읽지 않고
    기준으로 삼는다. 0.1.0 에이전트는 모르는 type이라 버린다.
- 포인터: **내 기기 포인터**(오너 결정 2026-10-14). 캡처에 커서를 넣지 않고 페이지는 영상 위에
  기본 화살표를 보인다. 에이전트는 포인터 이동마다 Mac 커서를 실제로 옮긴다(호버 동작 유지).
  Mac의 포인터 모양 변화(I자 등)는 보이지 않는다.
- 키보드: 물리 키 위치(`code`)를 Mac 가상 키코드로 바꾼다. 수식 키는 물리 위치 그대로
  (Ctrl→Control, Alt→Option, Win/Meta→Command) — 지금 VNC 경로와 같은 동작이다. 한글은 Mac
  입력기가 처리한다. Windows의 한/영 키(`code` `Lang1` 또는 `key` `HangulMode`)는 Mac Caps Lock
  한 번(한/A 전환)으로 보낸다(O3). 모르는 `code`는 버린다. OS가 가로채는 조합(Alt+Tab 등)은
  범위 밖이다.
- 텍스트 입력 창: `agent`는 `text`로 보내 에이전트가 유니코드 문자 입력 이벤트로 직접 친다(Mac
  클립보드를 건드리지 않는다). 클립보드 동기화(`clipboard`)와는 별개의 경로다. Guacamole 경로는 지금 그대로.
- 끼임 방지: 페이지는 blur·전체 화면 전환·대화 상자·세션 종료 때 `release`를 보낸다. 에이전트는
  data channel이 닫히거나 세션이 바뀌면 눌린 키·버튼을 모두 놓는다. 또 세션의 상대에게서 패킷이
  하나도 오지 않은 지 3초가 되면(브라우저가 강제 종료되거나 네트워크가 끊긴 경우) 눌린 키·버튼을
  모두 놓는다. 이때 세션은 닫지 않는다(10초 무수신 종료는 그대로). 패킷이 다시 오면 다음 3초
  침묵 때 또 놓는다.
- 에이전트가 페이지로 보내는 data channel 메시지(0.2.0부터 넷):
  `{"type":"replaced"}`(D5), `{"type":"lock","locked":bool}`(세션 시작 때와 잠금 신호가 바뀔 때마다.
  신호는 `CGSSessionScreenIsLocked`가 아니라 콘솔 잠금 `IOConsoleLocked`; 화면만 꺼진 상태는 잠금이
  아니다), `{"type":"clipboard","text":...,"concealed":bool}`(감시 중 Mac 클립보드가 바뀌었을 때),
  `{"type":"clipboard-skipped","reason":...}`(`too-large`, `read-denied`, `locked-multiline`,
  `locked-empty`). 오래된 페이지는 `replaced`만 읽고 나머지는 무시한다. 클립보드 본문은 로그에
  남기지 않는다(이유와 바이트 수만).
- 잠금 화면 붙여넣기: 잠겨 있을 때 Command만 누른 V를 주입하지 않고 들고 있던 클라이언트 텍스트를
  키코드로 친다(ABC 자판에 없는 문자는 유니코드 입력으로 대체). 들고 있던 텍스트는 Mac 클립보드에
  쓰지 않으며 잠금 해제와 세션 종료 때 버린다. 끝의 줄바꿈 하나는 지우고, 그래도 줄바꿈이 남으면
  치지 않고 `locked-multiline`을 알린다. 들고 있는 텍스트가 없으면 `locked-empty`를 알린다.

### D5. 세션 수명과 상태

- 에이전트당 세션 하나. 새 offer는 기존 세션을 닫고 넘겨받는다(다른 기기에서 이어 쓰기).
  밀려나는 세션의 피어를 닫기 전에 에이전트가 그 data channel로 `{"type":"replaced"}`를 보내고
  곧바로 연결을 닫는다. 페이지는 이 메시지를 받으면 바로 세션을 끝내고 "다른 기기에서
  연결했습니다" 화면(다시 연결 가능)으로 간다. 자동 재연결은 하지 않는다.
- 페이지는 첫 프레임이 표시되면 "연결됨", 연결이 `failed`/`closed`가 되거나 data channel이
  닫히면 "연결이 끊겼습니다" 화면으로 간다. 연결이 `disconnected`인 채 3초 동안 이어지면 같은
  화면으로 간다(3초 안에 `connected`로 돌아오면 취소). 에이전트가 재시작되거나 `replaced`가 닿지
  못한 경우를 `failed`(약 17초)까지 기다리지 않기 위해서다. 자동 재연결은 하지 않는다(현재 flow 규칙).
- 에이전트는 ICE consent가 끊기거나 10초 동안 아무것도 받지 못하면 세션을 닫고 캡처를 멈춘다.
- 에이전트 상태 `GET /v1/status`(토큰 필요): `screen`(권한 있음/없음), `accessibility`,
  `display`(정상/잠듦/없음), `locked`(잠금 화면 여부), `lastCaptureAt`(마지막으로 성공한 캡처
  시각), `version`. 값은 이 열거형과 시각뿐이고 화면 내용은 없다.
- 이 상태는 게이트웨이를 거쳐 타일과 오류 화면에 보인다(D7): "권한 필요", "잠김", "오프라인".
  P1은 첫 번째 갈래(에이전트로 잠금 해제)로 정해졌다(3절): 타일은 "잠김"이라고 말하지만
  열 수 있고, 에이전트는 잠금 화면에서도 세션을 연다(`REFUSE_WHEN_LOCKED = false`). 상태 거부로
  되돌리려면 두 값을 함께 뒤집는다. 30일 재확인으로 권한이 멈추면 "권한 필요"로 드러나고,
  오너는 VNC 타일로 들어가 재확인 창을 누른다(P4가 확인).
- 사용자가 로그아웃했거나 재부팅 뒤 로그인 전이면 에이전트가 없으므로 "오프라인"이다(FileVault
  재부팅 후 무인 로그인은 계속 범위 밖).

### D6. Mac 쪽 설치·갱신·제거

- 저장소 `agent/mac/`의 Rust 프로젝트. `Cargo.lock`을 커밋하고 `cargo build --locked`로만
  빌드한다.
- 최소 macOS는 14다(사용하는 ScreenCaptureKit API 때문). 더 오래된 시스템은 지원하지 않는다.
- `agent/mac/install.sh`를 오너가 Mac 터미널에서 실행한다(설치와 갱신 같은 스크립트, sudo 비밀번호
  입력 필요 — O4):
  1. 릴리스 빌드.
  2. 서명: 전용 키체인(`~/Library/Application Support/Gome Remote Agent/sign/`)의 자체 서명 코드
     서명 인증서, hardened runtime. 없으면 만든다. 이 키가 새면 같은 서명을 만들 수 있지만, 실행
     파일 경로가 root 소유이므로 허용을 가로채려면 관리자 비밀번호가 따로 필요하다.
  3. 기존 실행 파일을 `.prev`로 보관하고, 새 파일을 `/usr/local/libexec/gome-remote-agent`
     (root:wheel 755)에 둔다(sudo). 설정 `/usr/local/etc/gome-remote-agent/agent.json`(root:wheel
     644)을 처음 설치 때만 만든다.
  4. 토큰 `~/Library/Application Support/Gome Remote Agent/token`(600)이 없을 때만 만든다.
  5. per-user LaunchAgent `net.gome.remote-agent`: `RunAtLoad`, `KeepAlive`,
     `ProcessType=Interactive`. 로그 `~/Library/Logs/gome-remote-agent.log`, 크기 상한으로
     교체, 프레임 단위 로그 없음.
  6. 다시 띄운 뒤 10초 안에 `/v1/status`가 응답하지 않으면 `.prev`로 되돌리고 실패를 알린다.
  7. 처음 설치면 할 일을 보인다: 시스템 설정에서 두 권한 허용, 서버에서
     `set-credential <대상 ID> --agent-token` 실행 후 토큰 붙여넣기(토큰은 이때 한 번 화면에 보인다).
- 시작 거부: 바인딩 주소가 tailnet 주소가 아님, 설정 파일이 root 소유가 아님, 토큰 파일 권한이
  600이 아님, 게이트웨이 주소 없음. 권한이 없으면 실행은 하되 상태에 싣는다.
- 기본 포트 18471(시험판 18470과 겹치지 않음).
- `uninstall.sh`: LaunchAgent 해제, 실행 파일·설정·토큰·로그·전용 키체인 삭제(sudo), 시스템
  설정에서 항목을 지우라는 안내.

### D7. 게이트웨이 변경

- 대상 설정: `protocol: "agent"`(이때 `platform`은 `mac`이어야 함), `hostname`(tailnet 주소),
  `port`(기본 18471). `rdp`·`vnc`는 그대로다.
- 자격 증명 파서: 대상 방식별 항목 모양(D2)을 검사한다. 파일 전체 무효 규칙은 그대로다.
- `/api/targets`: `agent` 대상은 `ready` = `agentToken` 있음, `online`과 상태 = 에이전트
  `/v1/status`(2초 제한, 10초 캐시, 동시 요청 하나로 합침). 응답에는 열거형 상태만 싣는다.
- 새 경로 `POST /api/agent-sessions` `{targetId, width, height, sdp}`: 로그인·Origin 검사, JSON
  content-type, 본문 64 KiB 이하, `sdp`는 `v=0`으로 시작하는 문자열, 크기는 지금 한도. 에이전트
  `POST /v1/sessions`에 토큰과 함께 전달(10초 제한) → `{sdp}` 반환. 에이전트가 상태 이유로
  거절하면(권한 없음, 잠김) 그 코드를 페이지에 전달하고, 그 밖의 오류는 "연결할 수 없음"으로
  분류한다. 토큰 오류는 게이트웨이 로그에 구분해 남긴다.
- `set-credential.mjs`: `--agent-token` 추가, 대상 방식에 맞지 않는 입력 거부, 안내 문구
  ("VNC 비밀번호" 등)를 방식별로 고친다.
- 함께 고칠 곳: `scripts/init-gateway.mjs`와 `deploy/targets.example.json`(새 방식 예시),
  README(Mac 절, 자격 증명 안내, 운영 절), `docs/verification.md`, `test/ops.test.js`.

### D8. 페이지와 앱 변경

- 새 모듈이 `agent` 세션을 맡는다(WebRTC 연결, 영상 표시, 입력 수집, 크기 변경). 목록·연결
  중·오류 화면, 메뉴, 전체 화면, 다시 연결은 기존 흐름(`flow.ts`)을 그대로 쓰고, Guacamole
  경로(`rdp`·`vnc`)는 바꾸지 않는다.
- 해상도 선택은 `agent`에서도 켜진다(자동 기본).
- 브리지 버전 3: `viewer-state`의 `protocol`에 `agent`를 더한다. 브리지 2 이하 앱에는 `rdp`로
  보낸다(메뉴 동작이 같다: 해상도 사용 가능). 앱 모드 판정 기준은 그대로 1.
- 브리지 버전 4: 앱이 클립보드 읽기·쓰기 채널(`clipboard-read`, `clipboard-write`)과 키보드 잠금용 HTML
  전체 화면을 더한다. 페이지가 이를 쓸 수 있다고 표시한(`window.__gomeFsLock`) 때만 HTML 전체 화면을
  쓰고, 표시가 없는 이전 페이지에는 기존 전체 화면을 쓴다. 브리지 3 이하 앱에서는 페이지가 클립보드
  동기화와 키보드 잠금을 켜지 않는다.
- CSP는 바꾸지 않는다. 실제 앱에서 확인한다(V2, V3).
- 측정 모드: 주소에 `#measure`가 있을 때만 작은 패널이 뜨고, 지정한 위치에 클릭 N번을 보내
  표시된 화면의 픽셀이 바뀌는 시각을 같은 폴링 루프로 잰다(`agent`와 `vnc` 모두 같은 코드, 8절).
  평소에는 아무것도 하지 않는다.

### D9. VNC 타일은 대체 경로로 계속 둔다

- 전환 뒤에도 VNC 대상을 "Mac (VNC)"로 남긴다. 용도: 잠금 해제의 대체 경로(P1은 에이전트로 해제하는 쪽으로
  정해졌다), 30일 재확인 창 누르기, 에이전트 고장 때 복구와 재설치 안내, 되돌리기.
- 그래서 Mac 계정 비밀번호는 서버에 남는다(VNC 대상 항목). 이를 지우는 것은 별도 오너 결정(O2)이며
  이 작업에서는 하지 않는다.

### D10. 저장소와 CI

- `agent/mac/`은 Cargo 프로젝트. CI에 macOS 작업 추가: `cargo fmt --check`,
  `cargo clippy -D warnings`, `cargo test --locked`(키 변환표, 메시지 검사, 인증·Host·출처 검사,
  후보 필터, 크기 계산), `cargo deny check`(알려진 취약점·라이선스). 공개 저장소 위생 검사는 새
  파일에도 적용된다(tailnet 대역 상수는 위생 검사에 걸리지 않는 형태로 쓴다).
- 시험판 브랜치는 main에 넣지 않는다.

## 6. 오류 처리

- 에이전트 꺼짐/응답 없음 → 타일 "오프라인", 연결 시도 시 "연결할 수 없습니다".
- 권한 없음 → 타일과 오류 화면 "Mac에서 화면 기록·손쉬운 사용 권한이 필요합니다. Mac (VNC)로
  들어가 허용할 수 있습니다".
- 잠김(P1 결과가 입력 불가일 때) → "Mac이 잠겨 있습니다. Mac (VNC)로 잠금을 해제하세요".
  P1은 입력 가능이었으므로 지금은 에이전트가 이 거절을 하지 않는다. 상태 거부로 되돌릴 때의 문구다.
- 토큰 불일치 → 페이지는 "연결할 수 없습니다", 게이트웨이 로그에 원인. 에이전트는 응답을 늦춤.
- ICE 실패, 또는 연결이 3초 넘게 `disconnected` → "연결이 끊겼습니다".
- 다른 기기가 세션을 넘겨받음 → "다른 기기에서 연결했습니다"(다시 연결 가능, 자동 재연결 없음).
- 에이전트 비정상 종료 → LaunchAgent가 다시 띄운다. 세션은 끊김 화면.

## 8. 검증

측정 도구(D8 측정 모드): 같은 코드로 `agent`와 `vnc`를 잰다. Mac에서 시험 페이지(클릭마다 큰
영역의 색이 바뀜)를 띄우고, 클릭 송신 시각부터 표시된 화면(VNC 캔버스, 에이전트 영상을 그린
캔버스)의 지정 픽셀이 바뀐 것을 같은 폴링 루프(1 ms 단위)가 처음 본 시각까지를 잰다. 시험 페이지의
클릭 횟수와 측정 횟수가 같아야 유효하다: 시험 페이지가 센 바뀜(flip) 횟수는 n + 2여야 한다(앞선
시험 클릭 2번이 더해진다).

자동(CI): 게이트웨이 새 경로(가짜 에이전트: 인가·Origin·content-type·크기·본문 한도·토큰
전달·시간 초과·상태 코드 전달·오류 분류), `/api/targets` 상태(시간 제한·캐시), 자격 증명 방식별
항목 검사와 `--agent-token`, 대상 설정 검사, 페이지 `agent` 모듈(가짜 `RTCPeerConnection`: RTX
코덱 선호 유지, 입력 메시지 모양·정규화·끼임 방지, 크기 변경, 끊김 흐름: 3초 `disconnected`·`replaced` 통지), 브리지 3과 이전 앱 호환,
에이전트 단위 테스트(세션 교체 통지, 3초 침묵 키 해제 포함)와 `cargo deny`(D10).

실기기(9절의 병행 후보에서):

- V1. 에이전트: S2(게이트웨이 서버 클라이언트), S3, S4(`tc`로 수신 5 Mbps 제한), 정지 화면
  대역폭과 에이전트 CPU 기록.
- V2. 오너: Windows 앱 → "Mac (새 방식)" 타일 → 마우스·드래그·스크롤·키보드·한글·한/영·텍스트
  입력 창·해상도 자동·전체 화면·다시 연결(S1), 측정 모드로 S2·S3, 체감(S5).
- V3. 오너: Mac 앱에서 V2 반복.
- V4. 에이전트: 잠금 화면(P1 결과대로), 디스플레이 잠든 상태에서 연결, 다른 기기로 넘겨받기,
  에이전트 강제 종료 후 재기동, 끊긴 뒤 키 끼임 없음, 권한을 끈 상태에서 타일·오류 문구.
- V5. 에이전트: 음성 시험 — 틀린 토큰, 게이트웨이가 아닌 tailnet 주소에서 호출, `Origin` 있는 호출,
  허용 목록 밖 로그인, 설정 경로 인자 무시가 모두 거부·무시됨.
- V6. 전환·되돌리기 리허설(9절 5단계 전, 오너에게 알린 짧은 시간에): 9절 5단계 순서 그대로 전환한 뒤
  `:8450`에서 Ubuntu·Mac(새 방식)·Mac(VNC) 접속을 확인하고, 되돌리기 순서 그대로 옛 게이트웨이로
  돌려 다시 확인한다. 에이전트 `install.sh`의 `.prev` 되돌리기를 한 번 실행한다.

증거는 `docs/verification.md`(식별자 없이)와 비공개 인계 기록에 남긴다.

## 9. 운영 반영과 되돌리기

redesign 8절과 같은 병행 방식이다. 운영 게이트웨이(`gome-remote-gateway-v2`, 설정·자격 증명 파일,
Serve `:8450`)는 5단계 전까지 건드리지 않는다.

1. 시험판은 P4 관찰(2026-11-12)이 끝날 때까지 둔다. 포트(18470/18471)와 권한 항목이 달라 새
   에이전트와 함께 있을 수 있다. 그동안 같은 Mac에 화면 기록 권한을 가진 프로그램이 둘이고, 시험판은
   토큰이 필요한 `/offer`와 공개 `/stats`·`/trace`·`/target`으로 tailnet에서 응답한다. P4가 끝나면
   시험판 LaunchAgent를 내리고 `~/gome-agent-spike`(토큰, 전용 키체인 포함)를 지우며, 오너가 시스템
   설정에서 시험판 권한 항목을 지운다. 이 철거는 5단계 전에 끝낸다.
2. 에이전트 설치: 오너가 Mac에서 `install.sh` 실행, 두 권한 허용.
3. 병행 게이트웨이: 새 후보를 `~/remote-candidates/<버전>`에 두고 **새 unit·새 설정 파일·새 자격 증명
   파일**로 unix socket에서 띄운다. Serve에 새 포트(예: `:8451`) 하나만 더한다(추가 전 Serve JSON
   백업, 추가 뒤 `:443`·`:8450` 경로 동일 확인). 새 설정의 대상: Ubuntu(rdp), "Mac (새 방식)"
   (`agent`), "Mac (VNC)"(`vnc`). 오너가 새 자격 증명 파일에 세 항목을 `set-credential`로
   입력한다(Ubuntu 시스템 Remote Login 값, Mac 계정, 에이전트 토큰). 운영 파일은 읽지도 고치지도
   않는다.
4. V1~V6. 오너는 새 포트 주소로 앱이나 브라우저를 연다.
5. 전환(오너 승인 후). 게이트웨이는 요청 출처를 설정의 `publicOrigin`(포트 포함)과 정확히 비교하므로,
   시험 기간의 새 설정은 `:8451` 출처이고 전환에는 이 값을 바꾸는 단계가 필요하다. 순서:
   1. 새 설정을 백업하고 `publicOrigin`을 `:8450` 출처로 바꾼다. "Mac (새 방식)"을 "Mac"으로 이름을
      바꾼다. 새 unit을 재시작한다(이 순간부터 `:8451`로는 403, 운영 `:8450`은 아직 옛 게이트웨이).
   2. Serve `:8450`을 새 socket으로 돌린다(전후 Serve JSON 백업·비교).
   3. `:8450`에서 목록·Ubuntu·Mac 두 타일을 확인한다. 실패하면 Serve `:8450`을 옛 socket으로 즉시
      되돌린다(옛 unit은 아직 돈다).
   4. 확인되면 옛 unit을 멈춘다(지우지 않는다). Serve `:8451`을 끈다. 앱 주소는 그대로 `:8450`이다.
6. 사후 점검: 1차 신호는 오너가 앱을 열 때 보는 타일 상태다(D5). 그에 더해 전환 +1일, +7일, +30일
   (30일 재확인 날짜 포함)에 코딩 에이전트 세션이 타일 상태, `lastCaptureAt`, Mac 에이전트 로그를
   확인하고 비공개 인계 기록에 남긴다. 날짜는 인계 기록에 미리 적어 두고, 그 날짜 이후 첫 세션이
   수행한다. 이상이 있으면 오너에게 알린다.

되돌리기:

- 5단계 이후: 옛 unit을 다시 켜고 Serve `:8450`을 옛 socket으로 되돌린다. 옛 설정·자격 증명 파일은
  손대지 않았으므로 그대로 동작한다(V6에서 리허설). 새 게이트웨이를 다시 시험하려면 새 설정의
  `publicOrigin`을 백업대로 `:8451`로 돌리고 Serve `:8451`을 다시 켠다.
- 에이전트: `install.sh`가 실패 시 `.prev`로 되돌린다. 완전히 빼려면 `uninstall.sh`.
- 부분 실패: 1~4단계의 실패는 운영 게이트웨이에 영향이 없다(파일과 unit이 따로다). 새 unit 중지와
  Serve 새 포트 해제로 끝난다. 1단계 이후 에이전트가 없더라도 VNC 경로는 그대로다.

## 10. 오너 결정

- O0(확정 2026-10-08): 코덱은 H.264. AV1은 하드웨어 인코더가 없어 뺐다.
- O1(확정 2026-10-14): 포인터는 내 기기 포인터.
- O2: 서버에 보관한 Mac 계정 비밀번호를 언젠가 지울지. 이 작업에서는 지우지 않는다(D9의 VNC 대체
  경로가 쓴다). 지우면 VNC 타일이 동작하지 않으므로 대체 경로를 포기하는 결정이다.
- O3: 한/영 키를 Mac Caps Lock으로 보내는 것은 Mac의 "Caps Lock으로 ABC 입력 소스 전환" 설정을
  전제한다. 다른 전환 키를 쓰면 알려 주면 맞춘다.
- O4: 에이전트 갱신마다 오너가 Mac 터미널에서 `install.sh`를 실행하고 관리자 비밀번호를 넣는다
  (root 소유 경로 때문). 대안은 사용자 경로 설치(비밀번호 불필요, 대신 같은 사용자 코드가 허용을
  가로챌 수 있음). 제안: root 경로. 구현·검증 기간의 잦은 갱신은 시험판처럼 사용자 경로의 개발용
  설치로 하고, 운영 설치(9절 2단계)부터 root 경로를 쓴다.

## 11. 범위 밖

소리, 파일 전송, 이미지·파일 클립보드(텍스트 동기화는 D4), 여러 디스플레이, Mac 포인터 모양 표시,
잠금 해제 자동화(붙여넣기 한 번을 키코드로 치는 것만 D4에 있고, 그 밖의 잠금 화면 조작은 없다), 앱 서명·공증·자동 업데이트, Apple 지속 캡처 entitlement, Windows/Linux용 에이전트(Ubuntu는
guacd 유지), 휴대폰 입력 최적화, 재부팅 후 무인 로그인, TURN 중계(P2가 요구하지 않는 한).
